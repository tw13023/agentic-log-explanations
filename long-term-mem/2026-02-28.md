### 2. HDFS Hallucination 根本原因分析 ✅

經深入檢查 evidence store、retriever、prompt builder、verifier 後，確認 HDFS pipeline 有五層結構性問題：

**問題 1：Signature 完全缺失**
- HDFS `normalized_signature` 全部為 `None`（2,527 sessions）
- LLM 產生的 signature 66.3% 都是 `DATANODE__BLOCK_VERIFICATION_FAILED`
- 對比 BGL 有 57 種 normalized signatures

**問題 2：Evidence 極度同質化**
- 50 個 HDFS sessions 只用了 20 組 unique evidence sets
- 14 個 session 共用完全相同的 5 條 evidence
- 另外 11 個 session 共用另一組 5 條 evidence
- 原因：normalize 後 anomaly/normal sessions 的前 200 字元幾乎完全相同（都以 `Receiving block <BLOCK>` 開頭），BM25 無法區分

**問題 3：STRUCTURAL Summary 不對稱**
- Evidence store documents (E1-E5) 包含 `STRUCTURAL: receives=3 received=2 ... INCOMPLETE_PIPELINE` 行
- 但 E0 (query session) 使用 raw log lines，**不含 STRUCTURAL summary**
- BM25 query 也不含 structural tags（使用 `normalize_lines()` 而非 `normalize_session()` + `structural_summary()`）
- 結果：BM25 無法根據結構特徵做 query-evidence matching

**問題 4：52% 的 HDFS Anomaly 是 Pure-INFO**
- HDFS anomaly evidence: 11,786 sessions
- 包含 WARN: 48%（5,661）
- 包含 ERROR: 0%
- Pure INFO（但有 STRUCTURAL 標記）: 52%（6,125）
- Anomaly 是「結構性」的（缺少 acknowledgment、pipeline 不完整），不是文字上可見的 error

**問題 5：Verifier 只檢查格式**
- 8 項 verification checks 全是結構性的（JSON 結構、evidence ID、span 格式）
- 不檢查 cited lines 是否真的包含 error/warn
- E0 line count hardcoded 為 100（但 HDFS sessions 2-50+ 行不等）

**問題 6：Pattern discriminative_score 全為 ~0.0**
- `patterns/hdfs_patterns.json` 中所有 26 個 patterns 的 `discriminative_score` 趨近 0
- 表示 anomaly 與 normal sessions 共享幾乎相同的詞彙
- Anomaly 信號是 **sequential/structural**，不是 **lexical**

## Session 3: Auto-Evaluation & 500-Anomaly Scale-Up

### 9. Auto-Evaluator 建立 ✅

**新增 `pipelines/auto_evaluator.py`（~535 lines）：**
Rule-based 自動評估 proxy，模擬 human evaluation 的 C/Co/E 三維度評分。

**評分邏輯：**
- **C (Correctness, base 5)**: -2.0 verification FAIL, -0.5 each keyword_match WARNING (max -1.5), -1.0 signature missing, -0.5 cited_severity WARNING, -0.5 wrong prediction
- **Co (Coherence, base 5)**: -1.0/-2.0 claim types < 3, -0.5 short summary, -0.5 duplicates, -0.5 few claims
- **E (Evidence, base 5)**: coverage gap deduction, -1.0 spans_validity FAIL, -0.5 span_keyword WARNING, -0.5 no E0 spans, -0.5 each claim without spans
- **Y/N threshold**: avg(C, Co, E) >= 3.0

**API**: `AutoEvaluator.evaluate_pipeline(pipeline)` 或 `evaluate_jsonl(path)` → `EvaluationReport`

### 10. Verifier: Structural Anomaly Severity Bypass ✅

**修正**: 在 `_check_cited_severity()` 加入 bypass — 若整個 session 零 severity keywords → 回傳 PASS（"Structural anomaly — severity check not applicable"）。

### 12. Architecture Q&A: Signature Cards & BM25 ✅

深入分析 signature cards 在 pipeline 中的角色：

- **Signature cards 來源**: 僅從 training data 產生（`notebooks/05_signature_audit.ipynb`），存為 `patterns/*.json` 靜態檔案（BGL 34 張, HDFS 26 張）
- **載入方式**: Pipeline setup 時以 `EvidenceDoc(evidence_type="signature", label=-1)` 加入 evidence store
- **BM25 影響**: cards 貢獻到 BM25 vocabulary/IDF 計算，但在 `retrieve_mixed()` 中被 label=-1 過濾，**不會出現在 top-k results 中**
- **LLM 不會寫回**: LLM 只產生 signature name（string label），不會產生新 cards 或修改 evidence store
- **設計選擇 (Design A)**: Cards 影響 BM25 index 但不佔 top-k slot，這是正確的設計 — 避免浪費寶貴的 context window
