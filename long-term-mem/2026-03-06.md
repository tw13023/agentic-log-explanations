### 2. Phase 0: RAGAS-style Baseline Metrics ($0 cost)

從現有 production JSONL (`explanations_BGL_20260301_112519.jsonl`, 6,295 sessions) 計算。

#### Metric 1: Faithfulness (adapted from RAGAS, Es et al., EACL 2024)

**RAGAS 原始公式**:
- Faithfulness = |V| / |Total Claims|
- |V| = 被 context 支持的 claims 數量（原文用 LLM-as-judge NLI）

**我們的 adaptation**（rule-based，因為有 structured output）:
- Faithfulness_session = (claims with valid evidence_id AND evidence_span) / total claims
- "Supported" 定義：claim 至少引用一個合法 evidence_id 且有至少一個 evidence_span

**結果**: Faithfulness = **1.0000** +/- 0.0000
- 6,295 sessions 全部 perfect
- 原因：pipeline 的 verifier 已強制 structured grounding，不合格的 explanation 會被重試
- 這是 pipeline design 的結果，不是偶然

#### Metric 2: Context Precision@K (adapted from RAGAS)

**RAGAS 原始公式**:
- CP@K = sum(Precision@k * v_k) / (number of relevant items in top-K)
- v_k = 1 if rank-k document is relevant, else 0
- Precision@k = (relevant items in top-k) / k

**我們的 adaptation**（reference-free，用 LLM citation behavior 定義 relevance）:
- 只計算 E1-E4（K=4），即 BM25 ranked anomaly evidence
- E5（normal contrast session）排除 — 它是另外選出的，不屬於 BM25 ranking
- v_k = 1 if E_k is cited in pattern_match claims (E_k in C_anomaly)
- C_anomaly = {E_j | E_j cited in pattern_match claims, j in {1,2,3,4}}
- E0 是 query session 本身，排除

**結果**: Context Precision@4 = **0.9799** +/- 0.0947
- Median = 1.0（過半數 sessions 的 ranking 完美）
- Evidence Utilization = 55.1%（LLM 平均引用 ~2.2 / 4 個 anomaly evidence）
- 0.98 表示 BM25 retriever 幾乎完美地把 LLM 會用的 anomaly evidence 排在最前面

### 3. Phase 1: Retrieval Overlap Analysis ($0 cost)

回應 advisor 的問題：「為什麼只用 train split 建 evidence store？用 whole dataset 會不會更好？」

**方法**:
1. 載入現有 train-only evidence store (332,356 docs)
2. 建立 whole-dataset evidence store (474,796 docs, 1.43x)
3. 用 `retrieve_for_session_mixed()` 對 100 個 sampled test anomalies 比較，正確分離 anomaly (E1-E4, top_k_anomaly=4) 和 normal (E5, top_k_normal=1)
4. Train-only evidence 從 production JSONL 重用（免重算）

**Performance note**: BM25 (rank_bm25) 對 474K docs 每個 query 約 10s，100 sessions 花 ~17 min。

**結果**:

| Metric | Value |
|--------|-------|
| Corpus size (train-only) | 332,356 |
| Corpus size (whole) | 474,796 |
| Anomaly overlap rate (E1-E4) | 88.25% |
| Top-1 anomaly match rate | 85.0% |
| E5 normal match rate | 57.0% |
| Perfect anomaly overlap (4/4) | 70.0% |
| New docs in anomaly top-4 | 0.47 / 4 |
| Sessions with 0 new docs | 70% |

**Anomaly Overlap Distribution (E1-E4)**:
- 0/4: 0 (0%)
- 1/4: 3 (3%)
- 2/4: 11 (11%)
- 3/4: 16 (16%)
- 4/4: 70 (70%)

**E5 正常對照 session**:
- Match rate = 57% — 較低是合理的，因為 normal sessions 數量多（~26萬），whole-dataset 增加 ~14萬個新 normal candidates
- E5 的差異不影響 anomaly evidence 品質

**解讀**:
- 70% 的 sessions anomaly overlap = 4/4（perfect match）— 大多數情況下四個 anomaly evidence 完全相同
- 88.25% anomaly overlap rate — 比之前混合計算的 75.2% 更高，因為排除了 E5 的干擾
- Top-1 match = 85% — 最佳匹配 anomaly evidence 幾乎總是相同
- 只有 0.47 個 non-train document 進入 anomaly top-4（70% 的 sessions 完全沒有新 doc）
- E5 match 較低（57%）是因為 normal doc pool 大幅增加，但不影響 explanation 品質
- 結論：**train-only corpus 在 anomaly retrieval 上是 empirically validated 的選擇**

### 4. RAGAS Metric Adaptation 說明（for methodology section）

**與 RAGAS 原文的差異**:

| Aspect | RAGAS 原文 | Our Adaptation |
|--------|-----------|----------------|
| Faithfulness judge | LLM-as-judge (NLI) | Rule-based (evidence_id + span 存在性) |
| CP relevance signal | Ground-truth answer | LLM citation behavior (reference-free) |
| CP scope | All retrieved docs | E1-E4 only (K=4); E5 normal contrast excluded |
| Justification | General QA evaluation | Structured output 使 rule-based 可行；無 ground-truth 標準答案 |

**Paper wording suggestion**:
> "We adapt the Faithfulness and Context Precision metrics from RAGAS (Es et al., 2024) to our structured explanation format. Faithfulness is computed as the fraction of claims supported by valid evidence citations with line-level span references. Context Precision@K measures the rank-aware alignment between BM25 retrieval ranking and the LLM's actual evidence usage, using a reference-free relevance signal based on citation behavior."

### 5. Phase 2: No-RAG Ablation ($3.12 cost, 37 min)

**方法**:
- 從 6,295 個 production sessions 中按 signature 比例抽樣 506 sessions（369 matched test sessions）
- **Note**: 所有 ablation 比較都使用 matched 的 369 sessions（RAG-on 和 No-RAG 相同樣本）
- 涵蓋 360 個 signatures
- 用 GPT-5.1 重新 explain，但 evidence_hits=[]（無 RAG evidence）
- 使用 dummy ScreenerOutput（pred=1, prob=1.0, margin=1.0）
- 結果存為 `results/ablation_no_rag_BGL.jsonl`

**結果**:

| Metric | RAG-on (n=369) | No-RAG (n=369) | Delta |
|--------|--------|--------|-------|
| Faithfulness | 1.0000 | 1.0000 | +0.0000 |
| Grounding Breadth | 0.6658 | 0.0000 | +0.6658 |
| Claims/session | ~3 | 3.0 | ~0 |

**發現**:
- Faithfulness = 1.0 for both — **因為 E0（query session）總是可用的**。verifier 只檢查 claims 是否引用合法 evidence_id + span，而 E0 永遠是合法的。
- **Grounding Breadth** 是真正的區分指標：RAG-on 有 66.58% 的 claims 引用外部 anomaly evidence (E1-E4)；No-RAG = 0%（只能引用 E0）
- No-RAG 的 LLM 只有 1/1107 個 claims hallucinate 了 E1（phantom citation）
- 7/369 sessions 設定了 `insufficient_evidence` flag（因為沒有可用的 external evidence）

**Grounding Breadth 定義**:
$$\text{Grounding Breadth}_\text{session} = \frac{\text{claims citing } E_j, j \in \{1,2,3,4\}}{\text{total claims}}$$

**解讀**:
- RAG 的貢獻不是提高 "claims 是否有證據引用"（faithfulness）—— 因為 pipeline 設計保證了這一點
- RAG 的真正貢獻是讓 LLM 能夠**跨 session 比對 anomaly patterns**，產生比 "只看自己" 更有深度的解釋
- 沒有 RAG，LLM 只能描述 query session 本身的特徵；有 RAG，LLM 能引用歷史 anomaly 來佐證其判斷

### 8. RQ3 Cost-Quality Gating Simulation: `notebooks/12_rq3_cost_quality_gating.ipynb`

建立 RQ3 成本-品質權衡分析 notebook，使用 GPT-5.1 full-run 結果（BGL 6,295 sessions + HDFS 2,527 sessions），模擬 6 種 gating 策略在 6 個 budget 水平下的 signature coverage、token savings、faithfulness、grounding breadth。

#### 資料來源
- BGL: `results/explanations_BGL_20260301_112519.jsonl` (6,295 sessions, 360 signatures)
- HDFS: `results_HDFS/explanations_HDFS_20260303_162016.jsonl` (2,527 sessions, 168 signatures)
- BM25 scores: `results/bm25_scores_BGL.json`, `results_HDFS/bm25_scores_HDFS.json`

#### Gating 特徵定義
- **Uncertainty**: $u(x) = 1 - \text{margin}$（screener confidence 的反面）
- **Novelty**: $n(x) = 1 - \text{bm25\_max} / \max(\text{bm25\_max})$（BM25 retrieval 相似度的反面）
- **Combined**: $\alpha \cdot u(x) + (1-\alpha) \cdot n(x)$

#### Phase 1: Distribution Analysis

**Margin 統計**:
- BGL: mean=0.9951, below 0.99 only 108/6295 (1.7%)
- HDFS: mean=0.9996, below 0.99 only 4/2527 (0.16%)
- 結論：screener 對絕大多數 sessions 信心極高，uncertainty 集中在接近 0

**u(x) vs n(x) 相關性**:
- BGL: r = -0.115（接近獨立）
- HDFS: r = -0.012（近乎完全獨立）
- 結論：兩個信號提供互補資訊，適合組合使用

**Signature 長尾分佈**:
- BGL: Top-1 signature 佔 2,336 sessions; 207/360 (57.5%) 為 singletons
- HDFS: Top-1 佔 515 sessions; 73/168 (43.5%) 為 singletons
- 結論：強 Zipf 分佈，coverage 非 trivial

#### Phase 2: Retrospective Gating Simulation

6 策略 x 6 budget levels = 36 evaluation points per dataset, total 72。

**策略說明**:
| Strategy | Selection Rule |
|---|---|
| Random | Uniform random (10-seed avg) |
| Uncertainty | Top-K by u(x) = 1 - margin |
| Novelty | Top-K by n(x) = 1 - bm25_max/max |
| Combined | Top-K by 0.5*u + 0.5*n |
| Stratified | Proportional per signature (min 1) |
| Oracle | Maximize unique signatures (privileged) |

4. **Alpha sensitivity** -- pure uncertainty (alpha=1.0) 在 combined strategy 中表現最佳（BGL coverage=0.7472, HDFS=0.6250），但仍不如 Stratified
5. **Novelty-only 和 Combined 表現差** -- 因為 margins near 1.0 使得 uncertainty signal 微弱，但 Stratified 利用 signature 結構直接確保 diversity
