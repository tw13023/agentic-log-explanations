### 1. HDFS Verification Failures Fixed ✅

- 33/2,527 HDFS sessions 因為 malformed `evidence_spans` 導致 verification 失敗

- 修復後重新 patch JSONL → 2,527/2,527 全部通過

### 2. HDFS Signature Normalizer (`HDFSNormalizer`) ✅

LLM 產生的 signature 名稱有三個問題：
- **Severity 洩漏**: `DATANODE_INFO__BLOCK_WRITE_FAILURE`、`DATANODE__INFO__BLOCK_WRITE_FAILURE`
- **命名不一致**: `BLOCK_RECEIVING_FAILED` vs `BLOCK_RECEIVE_FAILURE` vs `BLOCK_RECEIVER_ERROR`
- **Component 錯誤**: 某些 error type 被放在錯誤的 component 下

實作 `HDFSNormalizer.normalize_signature()`：
- 從任何位置 strip severity labels（prefix suffix、middle segment、already clean）
- `_ERROR_TYPE_CANONICAL` dict（22+ entries）合併近似名稱
- `_COMPONENT_MAP` 確保 error type 對應正確的 HDFS component
- 結果：26 unique → 10 unique signatures（500-session test）

### 3. BGL Signature Normalizer (`BGLNormalizer`) ✅

BGL 的問題更嚴重 — 500-session test 產生 71 unique signatures：
- Severity 洩漏：`KERNEL__FATAL__DATA_TLB_ERROR`
- Case 混亂：`KERNEL__FATAL_data_TLB_ERROR`、`KERNEL__FATAL__data TLB error interrupt`
- Verbose literal：`KERNEL__FATAL__kernel terminated for reason 1001`
- `RAS_` prefix：`RAS_APP_FATAL__CIOD_STREAM_ERROR`

實作 `BGLNormalizer.normalize_signature()`：
- `RAS_` prefix stripping
- Verbose pattern collapsing（kernel terminated、rts panic、ciostream、bad message header 等）
- `_ERROR_TYPE_CANONICAL` dict（TLB variants、CIOD variants、floating point 等）
- `_COMPONENT_MAP`（CIOD → APP、VPD → LINKCARD 等）
- 結果：71 → 24 unique signatures（offline），100 live test → 13 unique

## Senior Review & Improvement Plan

收到 senior 的 feedback，評估後決定採納以下改進。預計 2026-02-13 執行。

### Senior 的 5 個建議（摘要）

1. **Signature cards 不出現在 hits 太可惜** — 改成兩路檢索，卡片做 hint
2. **fingerprint 應做成檢索欄位** — Jaccard/containment score
3. **naming 規則與 normalize 邏輯要同一套** — prompt 要更硬的約束
4. **matched_evidence_ids 價值偏低** — 需定義可驗證的規則
5. **Pattern cards 的 frequency 造成 bias** — 加 discriminative score

### 我們的評估結論

| 建議 | 採納？ | 理由 |
|------|--------|------|
| 1. 兩路檢索 | **部分** | Retriever B 過度工程化，改用簡單 keyword overlap 做 signature hints 注入 prompt |
| 2. fingerprint 欄位 | **延後** | dict 規則已夠用，Jaccard 增加複雜度但收益有限 |
| 3. 更硬的 prompt 約束 | **採納** | 加 bad→good example + "exactly one `__`" 規則 |
| 4. matched_evidence_ids 驗證 | **延後** | 低優先級，claims 的 evidence_spans 已有更細粒度的 grounding |
| 5. discriminative score | **採納** | 資料已有（notebook 05），只需 propagate 到 pattern JSON |

### 關鍵設計洞察

Signatures 是 **open-set labeling** 問題（LLM 可創造新類別），因此 verification 採 soft constraints，
避免把新型態異常強制映射到舊類別，造成 label collapse。Normalizer 是 LLM 自由度與統計可聚合性之間的 pragmatic bridge。

## Tomorrow's Implementation Plan (2026-02-13)

### Phase 1: Signature Hints in Prompt（最大收益）

**目標**：讓 LLM 看到匹配的 pattern card 名稱，減少 normalizer 的改寫壓力

**步驟**：
1. 在 `src/prompt_builder.py` 加一個 `match_signature_cards(session_text, patterns)` 函式
   - 對每張 pattern card，計算 session text 與 card keywords 的 keyword overlap（簡單 containment score）
   - 回傳 top 3 匹配的 card names + scores
2. 更新 `PromptBuilder.build_prompt()` 接受 optional `signature_hints: List[str]` 參數
3. 在 user prompt 加一個 `SIGNATURE HINTS` 區塊：
   ```
   Similar known signatures: KERNEL__DATA_TLB_ERROR, KERNEL__DATA_STORAGE_INTERRUPT
   ```
   - 不算 evidence IDs，不進 `matched_evidence_ids`，只是「參考」
4. Wire 到 `explain_session()`（notebook + `pipelines/explain_all.py`）
   - 需要在 explain_session 中載入 patterns dict，呼叫 match 函式
5. ✅ 驗證：跑 100-session BGL test，比較 unique sig count（pre: 13 → ?）

**預估 token 增量**：~20 tokens/session（0.6%）

### Phase 2: Tighten System Prompt

**目標**：讓 LLM 更遵守命名規則，減少 severity leaking

**步驟**：
1. 在 `get_system_prompt()` 的 `=== SIGNATURE NAMING ===` 區塊加入：
   - Bad → Good examples：
     ```
     BAD:  KERNEL__FATAL__DATA_TLB_ERROR  (severity leaked)
     GOOD: KERNEL__DATA_TLB_ERROR
     BAD:  DATANODE__INFO__BLOCK_WRITE_FAILURE
     GOOD: DATANODE__BLOCK_WRITE_FAILURE
     ```
   - 明確規則：`"The name must contain exactly ONE __ separator"`
2. ✅ 驗證：與 Phase 1 一起跑同 100 sessions，測量綜合改善

**預估 token 增量**：~30 tokens/session（0.9%）

### Phase 3: Discriminative Score on Pattern Cards

**目標**：讓 signature hints 有品質信號，區分「關鍵型」vs「常見型」

**步驟**：
1. 用 `notebooks/05_signature_audit.ipynb` 已計算的 discriminative scores

   - high: score > 0.3, medium: 0.1~0.3, low: < 0.1
3. 更新 card text 生成（evidence store 注入時）：
   ```

   ```

**注意**：score 計算邏輯已在 notebook 05，只需 export 到 JSON
