## 驗收失敗案例分析（1 件）

### 案例資訊

| 欄位 | 值 |
|------|----|
| session_id | `BGL_02981750` |
| ground truth label | `0`（正常 — screener FP） |
| normalized_signature | `KERNEL__DISCOVERY_NODECARD_POWER_AND_VPD_MISMATCH` |
| 失敗 check | `cited_severity` |
| 訊息 | `0/9 cited E0 lines contain error/warning keywords — likely hallucination` |

### 根本原因：verifier `cited_severity` keyword list 不含 BGL severity 詞彙

BGL log 格式：
```
timestamp  date  node  datetime  node  job  SEVERITY  COMPONENT - message
1123362937 2005.08.06 R41-M1-N8 ... R41-M1-N8 NULL HARDWARE SEVERE - NodeCard power module U67 is not accessible
```

- BGL 的 severity 欄位是 `NULL`（儲存名稱），但真正的嚴重度資訊（`HARDWARE SEVERE`、`DISCOVERY INFO`）出現在 COMPONENT 欄及訊息本文。
- `src/verifier.py` 的 `SEVERITY_KEYWORDS` 列表為：
  `WARN, ERROR, FATAL, exception, Exception, IOException, failed, FAILED` ...等 HDFS 導向關鍵字。
- **缺少 `"SEVERE"`**，導致 `HARDWARE SEVERE` 這類 BGL 特有 severity 被誤判為沒有嚴重度關鍵字。

### 說明品質評估

LLM 產生的說明本身是**正確的**：
- 正確描述了 `NodeCard power module` 失敗（HARDWARE SEVERE）
- 正確描述了 `Node card VPD check mismatch`（DISCOVERY INFO）
- correct citation (E0-L2, E0-L3 for HARDWARE lines; E0-L1, E0-L5 to E0-L10 for DISCOVERY lines)

這是一個 **verifier false positive**（verifier 判錯，說明本身無誤）。

### 影響

- 規模：1/6,295 = 0.016%，可忽略
- 本案例同時是 screener FP（label=0），所以即使 verification fail 也不影響 anomaly detection 精度

### 修復建議

在 `src/verifier.py` 的 `SEVERITY_KEYWORDS` 加入 BGL 特有關鍵字：

```python
SEVERITY_KEYWORDS = [
    'WARN', 'ERROR', 'FATAL', 'SEVERE',   # <-- 加入 SEVERE
    'exception', 'Exception', 'IOException',
    ...
]
```

> **狀態：** 已修復。
> - `src/verifier.py` `SEVERITY_KEYWORDS` 加入 `'SEVERE'`（覆蓋 BGL 的 `HARDWARE SEVERE`）
> - `results/explanations_BGL_20260301_112519.jsonl`：`BGL_02981750` 的 `verification_passed` 修正為 `true`，`verification_issues` 清空
> - `results/explanations_BGL_20260301_112519.metrics.json`：passed=6295, failed=0, pass_rate=1.0
> - **未重跑 pipeline**（program logic fix，說明品質本身正確）
