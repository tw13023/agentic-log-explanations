## Today's Accomplishments

### 1. Gating 機制公式化設計 ✅

#### 1.1 問題定義

Pipeline A 對所有 predicted anomalies 呼叫 LLM 產生解釋，成本與延遲呈 $O(N)$ 成長。Gating 的決策問題：

> 在固定 LLM 預算下，從 $N$ 筆 predicted anomalies 中選出最有資訊價值的 $K$ 筆進行解釋，同時維持對所有故障類型的覆蓋。

#### 1.2 符號定義

| Symbol | Definition |
|---|---|
| $x$ | 一筆被 Screener 判定為異常的 session |
| $\mathcal{A} = \{x_1, \dots, x_N\}$ | 所有 predicted anomalies 集合 |
| $p_\text{anom}(x)$ | Screener 輸出的 anomaly probability |
| $m(x) = \|p_\text{anom}(x) - p_\text{norm}(x)\|$ | 信心邊際（margin），越大 = 越確定 |
| $\mathcal{E}(x) = \{e_1, \dots, e_k\}$ | 對 $x$ 的 top-$k$ BM25 retrieved evidence |
| $\text{bm25}_\text{max}(x)$ | 最高 BM25 evidence 分數 |
| $B \in (0, 1]$ | 預算比例 |
| $K = \lfloor B \cdot N \rfloor$ | 預算的絕對數量 |
| $S \subseteq \mathcal{A},\ \|S\| = K$ | 被選中進入 LLM 的子集 |

#### 1.3 特徵定義

**Feature 1: Uncertainty $u(x)$** — 來自 Screener 輸出（零成本）

$$u(x) = 1 - m(x)$$

- $m(x) = 0$（$p_\text{anom} = 0.5$，完全不確定）→ $u = 1$
- $m(x) = 1$（完全確定）→ $u = 0$
- 理論基礎：等同 active learning 中的 uncertainty sampling，決策邊界附近的樣本資訊量最大

**Feature 2: Retrieval Novelty $n(x)$** — 來自 BM25 檢索（已在 LLM 呼叫前完成，零額外成本）

$$n(x) = 1 - \frac{\text{bm25}_\text{max}(x)}{\max_{x' \in \mathcal{A}} \text{bm25}_\text{max}(x')}$$

- BM25 分數高 = evidence store 中有高度匹配的歷史案例 = 不新穎 → $n \to 0$
- BM25 分數低 = evidence store 中找不到相似案例 = 新穎/罕見 → $n \to 1$
- 因果正確：BM25 在 LLM 呼叫之前取得，無 chicken-and-egg 問題

**排除 Risk（session 長度）的理由：** BGL 使用固定滑動窗口 $w=10$，所有 session 恰好 10 行——長度為常數，無法提供區辨訊號。HDFS session 長度介於 1-55 行，變異有限。若未來應用到 variable-length datasets，可作為擴展。

#### 1.4 Gating Score

$$s(x) = \alpha \cdot u(x) + (1 - \alpha) \cdot n(x), \quad \alpha \in [0, 1]$$

單一超參數 $\alpha$ 控制兩個特徵的權重：

| $\alpha$ | 行為 |
|---|---|
| $1.0$ | 純 uncertainty（margin-only baseline） |
| $0.0$ | 純 retrieval novelty |
| $0.5$ | 均衡組合 |

#### 1.5 Selection

$$S^* = \underset{S \subseteq \mathcal{A},\ |S|=K}{\arg\max} \sum_{x \in S} s(x)$$

等價於：對所有 anomaly 按 $s(x)$ 降序排列，取前 $K$ 名。

#### 1.6 評估指標

**Primary — Signature Coverage（故障類型覆蓋率）：**

$$\text{Coverage}(S) = \frac{|\{\text{unique normalized signatures in } S\}|}{|\{\text{unique normalized signatures in } \mathcal{A}\}|}$$

- 使用 normalized signature（非 raw），避免 LLM 命名不一致導致 coverage 虛高
- 從 operations 角度：是否仍能觀察到所有故障類型

**Secondary — Cost（成本節省）：**

$$\text{Cost}(S) = \sum_{x \in S} \text{tokens}(x)$$

**Tertiary — Quality（解釋品質）：**

$$\text{VPR}(S) = \frac{|\{x \in S : \text{verification passed}\}|}{|S|}$$

預期 VPR 在各子集間維持接近 100%（因目前 full-run VPR 已 99.97–100%）。

### 2. 實驗設計 ✅

#### 2.1 回溯模擬方法（Retrospective Simulation）

利用 Pipeline A 已完成的 full-run 結果（BGL: 6,290 筆、HDFS: 2,527 筆），**直接從 JSONL 中篩選子集**模擬 gating 效果。

**方法論優勢：**
- 不需重新執行 LLM（節省 49+ 小時）
- 所有策略共享同一組 LLM 輸出，完全排除 LLM non-determinism 對策略比較的干擾
- 結果可完全重現

#### 2.2 實驗因子

| Factor | Levels |
|---|---|
| **Budget $B$** | 0.10, 0.20, 0.30, 0.50, 0.75, 1.00 |
| **Strategy** | Random (10 seeds), Uncertainty ($\alpha=1$), Novelty ($\alpha=0$), Combined ($\alpha=0.5$), Stratified, Oracle |
| **Dataset** | BGL, HDFS |

**策略說明：**

| Strategy | 選擇規則 | 目的 |
|---|---|---|
| **Random** | 均勻隨機取 $K$ 筆（10 seeds 取平均） | Naive baseline |
| **Uncertainty** | $s(x) = u(x)$，取最不確定的 $K$ 筆 | 核心假說 |
| **Novelty** | $s(x) = n(x)$，取 BM25 最差的 $K$ 筆 | 檢索新穎性假說 |
| **Combined** | $s(x) = 0.5u(x) + 0.5n(x)$ | 組合效果 |
| **Stratified** | 按 normalized signature 比例抽樣 $K$ 筆 | 操作性基線（保證按比例覆蓋） |
| **Oracle** | 事後最佳化——在 $K$ 筆限制下最大化 unique signatures | 理論上界 |

**總計：6 budgets × 6 strategies × 2 datasets = 72 evaluation points**（+ random 的 10 seeds）。

### 3. Edge Case 影響分析 ✅

檢視 Pipeline A 開發中遭遇的所有 edge cases 對 gating 的影響：

| Edge Case | 影響 Gating？ | 結論 |
|---|---|---|
| LLM Hallucination (2/6,290 BGL) | 間接。$n(x)$ 傾向保留此類 session | 正確行為（不確定案例值得解釋） |
| Truncation artifact (1/2,527 HDFS) | 不影響 | 已透過 char-budget 修正，屬 prompt 層 |
| Signature 命名不一致 (116→56 BGL) | 影響**評估** | Coverage 必須用 normalized signature |
| Contrast claim 缺失 (19/5,849 BGL) | 不影響 | Mixed retrieval 已解決 |
| LLM empty response (5/6,295 BGL) | 不影響 | 回溯模擬時排除 |
| Malformed spans (33/2,527 HDFS) | 不影響 | Verifier regex 已修正 |
| SUCCEEDED singleton (1/2,527 HDFS) | 不影響 | 0.04%，normalizer 處理 |
| **Signature long-tail (Zipf)** | **核心挑戰** | Gating 存在的根本理由 |

**關鍵設計洞察：** 大部分 edge cases 屬於 pipeline 其他層（prompt、verifier、normalizer），已在 Pipeline A 迭代中修正。Gating 的唯一職責是在固定預算下選出最有資訊價值的子集。Signature long-tail 分布（Zipf's Law）使得此選擇問題 non-trivial。

## Thesis Methodology Section: Formulations

以下為可直接引用於論文 Methodology section 的公式化定義：

### Budget-Constrained Explanation Allocation

**Problem.** Given a set of screener-flagged anomalies $\mathcal{A} = \{x_1, \dots, x_N\}$, a budget ratio $B \in (0,1]$, and a budget $K = \lfloor B \cdot N \rfloor$, select a subset $S^* \subseteq \mathcal{A}$ of size $K$ that maximizes explanation value while preserving error-type coverage.

**Gating Score.** For each candidate $x \in \mathcal{A}$, we define a gating score:

$$s(x) = \alpha \cdot u(x) + (1 - \alpha) \cdot n(x), \quad \alpha \in [0, 1]$$

where $u(x)$ captures screener uncertainty and $n(x)$ captures retrieval novelty.

**Uncertainty.** Derived from the screener's confidence margin:

$$u(x) = 1 - m(x), \quad m(x) = |p_\text{anom}(x) - p_\text{norm}(x)|$$

where $p_\text{anom}(x)$ and $p_\text{norm}(x)$ are the softmax probabilities from the AllLinLog screener. Sessions near the decision boundary ($m \to 0$) receive the highest uncertainty score.

**Retrieval Novelty.** Derived from BM25 evidence retrieval scores:

$$n(x) = 1 - \frac{\text{bm25}_\text{max}(x)}{\max_{x' \in \mathcal{A}} \text{bm25}_\text{max}(x')}$$

where $\text{bm25}_\text{max}(x)$ is the highest BM25 score among the top-$k$ retrieved evidence documents for session $x$. Sessions with poor evidence matches ($\text{bm25}_\text{max} \to 0$) receive the highest novelty score, indicating patterns underrepresented in the evidence store.

**Selection.** The gating selects the top-$K$ sessions by score:

$$S^* = \underset{S \subseteq \mathcal{A},\ |S|=K}{\arg\max} \sum_{x \in S} s(x)$$

**Evaluation.** The primary evaluation metric is signature coverage:

$$\text{Cov}(S) = \frac{|\Sigma(S)|}{|\Sigma(\mathcal{A})|}, \quad \Sigma(S) = \{\sigma_\text{norm}(x) : x \in S\}$$

where $\sigma_\text{norm}(x)$ denotes the normalized signature of session $x$, ensuring that evaluation is invariant to LLM naming non-determinism.
